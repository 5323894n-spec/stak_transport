# АТП-система (ATP Servis V2)

Веб-программа для автотранспортного предприятия: планирование, наряды,
путевые листы по форме № 6, проверки по Приказу Минтранса № 424, ремонт и ТО,
выручка, диспетчерский контроль, табель, выгрузка в 1С.

**Стек:** Python 3.10+ · FastAPI · SQLite (один файл `atp.db`) · uvicorn ·
ванильный JavaScript без сборки · openpyxl / python-docx для выгрузок ·
pytest + Node.js для тестов. Сборщика (npm/webpack) нет и не нужно.

**Интерфейс, комментарии, документация, сообщения об ошибках — на русском.**
Имена файлов, функций, полей БД и коммиты — на английском.

## Первый запуск на новом компьютере

Полная пошаговая инструкция: `references/новый-компьютер.md`.
Коротко (нужны Python 3.10+, Git, Node.js):

```bash
git clone https://github.com/5323894n-spec/stak_transport.git
cd stak_transport
python -m pip install -r requirements.txt
python run.py --demo          # http://127.0.0.1:8000, вход admin / admin
```

Двойным кликом для пользователя: `update.bat` (git pull + установка + запуск,
порт 8001) или `start.bat` (только запуск). В PowerShell — с префиксом `.\`.

## Как устроен проект

Карта модулей, схема БД, соглашения по коду: `references/architecture.md`.
Читай его перед первой правкой кода в незнакомом модуле.

```
run.py              запуск uvicorn (--demo, --port)
app/main.py         точка входа FastAPI, подключение всех роутеров
app/db.py           схема БД, миграции, аудит; путь к базе — env ATP_DB
app/auth.py         пользователи, сессии, роли, require_write(user, section)
app/norms.py        движок проверок Приказа № 424
app/api_*.py        REST-эндпоинты по разделам
app/*_service.py    бизнес-логика без FastAPI (тестируется отдельно)
app/*_reports.py    Excel/Word-выгрузки
static/             интерфейс: index.html + app.js + модульные *.js + styles.css
tests/              pytest (~120 файлов) + tests/js/ сценарии для Node
docs/superpowers/   specs/ (дизайн) и plans/ (планы реализации) по каждой фиче
```

## Обязательный порядок работы над задачей

1. **Дизайн → spec.** Новая фича начинается с обсуждения и файла
   `docs/superpowers/specs/ГГГГ-ММ-ДД-<фича>-design.md` (используй скилл
   `superpowers:brainstorming`). Формат — как у соседних файлов в папке.
2. **План.** `docs/superpowers/plans/ГГГГ-ММ-ДД-<фича>.md` — задачи с точными
   путями файлов и проверками (скилл `superpowers:writing-plans`).
3. **Ветка.** `git checkout -b codex/<короткое-имя>` — так называются все
   ветки фич в этом репозитории.
4. **TDD.** Сначала тест в `tests/`, он должен упасть, потом код. Тест на
   каждый новый эндпоинт, на выгрузку (структура листов Excel) и на интерфейс.
5. **Проверка.** `python -m pytest -q` целиком, зелёный прогон обязателен
   перед коммитом. Никогда не заявляй «готово» без вывода pytest.
6. **Коммит.** Conventional commits с областью: `feat(dispatch): ...`,
   `fix(schedule): ...`, `test(repair): ...`, `docs(...)`, `chore(...)`.
7. **Пуш.** `git push github <ветка>` (см. раздел про remotes ниже).

## Правила, которые легко нарушить

- **`atp.db` не в git** (в `.gitignore`) и на каждом компьютере своя. Перед
  обновлением или рискованной правкой схемы — копия файла `atp.db`.
- **Схему меняем только миграцией.** Новые таблицы/колонки добавляются в
  `migrate()` в `app/db.py` (или в `migrate_repairs` / `migrate_route_network`
  в `app/repair_schema.py` / `app/route_schema.py`) через `CREATE TABLE IF NOT
  EXISTS` и «добавить колонку, если её нет». Повторный запуск обязан быть
  безопасным — программа мигрирует базу сама при старте.
- **Новый JS-файл — прописать в `static/index.html`** и поднять номер версии в
  `?v=`, иначе у пользователей останется старый файл из кеша браузера. При
  правке существующего `app.js` / `dispatch.js` и т. п. версию тоже поднимаем.
- **Новый роутер — подключить в `app/main.py`** (`app.include_router(...)`).
- **Нормативы № 424 не хардкодим**: значения лежат в БД версиями с датами
  действия, проверки берут версию на дату.
- **Права доступа**: каждый пишущий эндпоинт вызывает `require_write(user,
  "раздел")`. Роли перечислены в `app/auth.py`.
- **Внешних JS-библиотек не добавляем.** Единственный вендор — Leaflet в
  `static/vendor/`. Графики — инлайновый SVG своими функциями.

## Тесты

```bash
python -m pytest -q                      # всё (нужен Node.js для части тестов)
python -m pytest tests/test_dispatch_api.py -q
```

- API-тесты поднимают `TestClient(app)` с временной базой: `db.DB_PATH =
  str(tmp_path / "x.db")`, `db.init_db()`, `ensure_admin(con)`, логин
  `admin/admin`, токен в заголовок `Authorization: Bearer`. Готовый пример —
  `_client()` в `tests/test_route_schedule_document.py`.
- Тесты интерфейса бывают двух видов: проверка исходника (`static/app.js`
  содержит нужные строки) и исполняемые сценарии `tests/js/*.js`, которые
  pytest запускает через `subprocess` + `node`. Без установленного Node.js эти
  тесты падают — это не поломка кода.

## Git: два remote

На домашнем ПК (`C:\atp-system-local`) настроены два адреса:

- `github` → `https://github.com/5323894n-spec/stak_transport.git` — основной,
  через него идёт синхронизация между компьютерами;
- `origin` → папка на Google Диске — резервная копия, **на другом компьютере
  её не будет**, там после `git clone` останется только `origin` = GitHub.

Поэтому: смотри `git remote -v` перед пушем и пуш в тот remote, что указывает
на github.com. Отправить наработки перед сменой компьютера:

```bash
python -m pytest -q && git push github main
```
