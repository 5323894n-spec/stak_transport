# Модуль «Сводное расписание»

## Решение

Реализуется вариант А: отдельный модуль-снимок «Сводное расписание».

Модуль добавляется как новый раздел главного меню и становится связующим слоем между маршрутными расписаниями, графиками водителей, нарядами и путевыми листами. Он не заменяет существующий конструктор расписаний и не ломает текущую генерацию графика или наряда. Сводное расписание собирается из уже существующих таблиц, сохраняется как версия и может быть проверено, выгружено в Excel и передано в наряд.

## Цели

- Сформировать единую диспетчерскую таблицу на дату или период.
- Собрать рейсы всех маршрутов в один оперативный документ.
- Показать данные по маршрутам, выходам, водителям, автобусам и времени.
- Автоматически выявить ошибки и предупреждения.
- Сохранить историю формирования и версии.
- Выгрузить красивый Excel-файл с титульным листом, сводкой и основными таблицами.
- Создать наряд на выбранную дату на основании сохраненного сводного расписания.

## Важное ограничение текущей модели

В текущей базе `route_trips` хранит рейсы маршрута по типу дня, но не хранит отдельный статус расписания `Утверждено`, `Действует`, `Черновик`, `Архив`, `Отменено`.

В первом этапе правило отбора такое:

- действующими считаются рейсы активных маршрутов `routes.active=1`;
- тип дня определяется по календарю через уже существующую функцию `sched_day_type`;
- статус версии сводного расписания хранится в новых таблицах;
- фильтр «только действующие» в первом этапе исключает неактивные маршруты;
- полноценный статус версий маршрутных расписаний можно добавить отдельным будущим этапом без переделки сводного модуля.

## Источники данных

Используются существующие таблицы:

- `routes`;
- `route_trips`;
- `calendar`;
- `roster`;
- `roster_assignments`;
- `drivers`;
- `buses`;
- `absences`;
- `norms`;
- `orders` и `order_lines` при формировании наряда;
- `settings` для названия организации и реквизитов в Excel.

Приоритет назначения водителя:

1. `roster_assignments` на конкретную дату, маршрут, выход и смену.
2. Агрегированная строка `roster` на дату, маршрут, выход и смену.
3. Если водитель не найден, строка попадает в сводное расписание с ошибкой `Не назначен водитель`.

Приоритет назначения автобуса:

1. автобус, закрепленный за найденным водителем через `drivers.assigned_bus_id`;
2. автобус, закрепленный за маршрутом или водителем в существующих справочниках, если такие данные есть;
3. если автобус не найден, строка попадает в сводное расписание с ошибкой `Не назначен автобус`.

## API

Добавить endpoints:

- `GET /api/summary-schedules`: история версий с фильтрами.
- `POST /api/summary-schedules/generate`: сформировать и сохранить снимок.
- `GET /api/summary-schedules/{id}`: получить снимок, сводку, строки, ошибки и представления.
- `GET /api/summary-schedules/{id}/export.xlsx`: выгрузить Excel.
- `POST /api/summary-schedules/{id}/check`: пересчитать ошибки по сохраненному снимку.
- `POST /api/summary-schedules/{id}/order`: сформировать наряд на дату из сводного расписания.
- `POST /api/summary-schedules/{id}/status`: изменить статус версии.

Параметры генерации:

```json
{
  "date_from": "2026-07-09",
  "date_to": "2026-07-09",
  "route_ids": [],
  "day_type": "",
  "include_inactive": false,
  "include_drafts": false,
  "comment": ""
}
```

Если выбран период больше одного дня, формируется общий снимок по всем датам периода. Формирование наряда из сводного расписания разрешено только для одной даты.

## Проверки ошибок

Система выявляет:

1. Не назначен водитель.
2. Не назначен автобус.
3. Один водитель назначен одновременно на два выхода.
4. Один автобус назначен одновременно на два выхода.
5. Пересечение рейсов по времени.
6. Не указано время отправления.
7. Не указано время прибытия.
8. Время прибытия раньше времени отправления.
9. Не указан номер маршрута.
10. Не указан номер выхода.
11. Не указан номер рейса.
12. Расписание не действует на выбранную дату.
13. Расписание находится в черновике, если в будущем появятся статусы маршрутных расписаний.
14. Автобус находится в ремонте.
15. Водитель находится в отпуске или на больничном.
16. Нарушен режим труда и отдыха водителя.
17. Дублируются номера рейсов внутри выхода.
18. Дублируются номера выходов в неоднозначном контексте маршрута и даты.

Ошибки 424 остаются предупреждениями и не блокируют просмотр или экспорт. Формирование наряда блокируют только критические ошибки.

## Цветовая индикация

- зеленый: данные корректны;
- синий: информационный статус;
- желтый: предупреждение;
- оранжевый: требуется проверка;
- красный: критическая ошибка;
- серый: архивное или неактивное расписание.

## Формирование наряда

Кнопка `Сформировать наряд` доступна для снимка с одной датой.

В наряд передаются:

- дата;
- маршрут;
- выход;
- рейсы;
- водитель;
- автобус;
- госномер;
- гаражный номер;
- время выезда;
- время начала работы;
- время окончания работы;
- время заезда;
- пробег;
- примечание.

Если в сводном расписании есть критические ошибки, наряд не формируется. Пользователь видит список критических ошибок и рекомендации.

Если наряд на дату уже существует, используется существующая логика защиты от перезаписи: пользователь должен явно подтвердить пересоздание или сначала отменить утверждение наряда.
