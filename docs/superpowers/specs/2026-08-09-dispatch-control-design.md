# Модуль «Диспетчер» — операционный контроль дня — дизайн

**Дата:** 2026-08-09
**Статус:** согласован (полный объём, включая GPS-симулятор, Excel-отчёт, переключатель источника на дату)

## Цель

Добавить оперативный контроль работы маршрутов в течение суток: **табло выпуска
на линию** и **порейсовую регулярность** движения, поверх утверждённого наряда
на день. Источник факта переключается между **ручным вводом** и **GPS/телеметрией**
на каждую дату. Это следующий пассажирский модуль после «Билеты и выручка».

## Ключевые решения (согласованы)

1. **Оба контура** — табло выпуска и регулярность — в одном разделе «Диспетчер».
2. **Переключатель источника** факта на дату: `ручной | GPS`. Обе ветки пишут в
   одни и те же таблицы; рендер табло/регулярности не зависит от источника.
3. **GPS** реализуется как шов приёма телеметрии (`POST /api/dispatch/telemetry`).
   Реальная интеграция/карта в реальном времени — позже (YAGNI). Для демонстрации
   режима — кнопка-симулятор, отправляющая телеметрию.
4. Основа — утверждённый **наряд на день** (`order_lines` = выходы). Плановое
   время выпуска = `order_line.depart_depot` (иначе `start_line`). План рейсов —
   из `route_trips` по маршруту/выходу/смене и типу дня (`sched_day_type`).

## Компоненты

### `app/dispatch_service.py` (без FastAPI)
- `ensure_day(con, date) -> dict` — вернуть/создать запись дня.
- `set_source_mode(con, date, mode, *, user)` — переключить `manual|gps`.
- `build_board(con, date) -> dict` — по утверждённому наряду собрать строки
  выходов (маршрут, выход/смена, водитель, автобус, план/факт выпуска,
  отклонение, статус, причина), подтягивая/создавая `dispatch_outputs`.
  Плановое время выпуска берётся из наряда. Если наряда/утверждения нет —
  пустой список + флаг `has_order=False`.
- `set_output_status(con, output_id, status, *, at=None, reason=None, user)` —
  переход статуса; для `выпущен` фиксирует `actual_release` (по умолчанию
  текущее время, редактируемо) и считает `deviation_min`; для `сошёл/срыв/замена`
  требует `reason`. Валидные переходы описаны в сервисе.
- `list_trip_facts(con, date, order_line_id) -> list[dict]` — план рейсов из
  `route_trips` (по маршруту/выходу/смене и `sched_day_type(date)`) c наложенным
  фактом из `dispatch_trip_facts`.
- `set_trip_fact(con, order_line_id, trip_number, actual_dep, *, user)` —
  сохранить факт, посчитать `deviation_min` и `on_time` по допуску.
- `apply_telemetry(con, payload, *, user)` — в режиме `gps` применить событие
  (`release|on_line|off_line|disruption|trip_departure`) к выходу по автобусу
  (`garage_number`/`vehicle_id`); в режиме `manual` — отклонить (409).
- `day_summary(con, date) -> dict` — КПД: план выходов, выпущено, на линии,
  сходы, срывы, замены; регулярность выпуска % (выпущено вовремя / план);
  регулярность рейсов % (on-time / всего зафиксировано). Срыв и большое
  отклонение → `db.notify(...)`.

Мутации пишут `db.audit`, не коммитят (коммитит API).

### `app/api_dispatch.py` — REST (`/api/dispatch`)
- `GET /board?date`, `GET /adherence?date&order_line_id`, `GET /summary?date`.
- `PUT /source-mode` `{date, mode}`.
- `POST /outputs/{output_id}/status` `{status, at?, reason?, note?}`.
- `PUT /trips/{order_line_id}/{trip_number}` `{actual_dep}`.
- `POST /telemetry` `{date, garage_number|vehicle_id, event, time?, trip_number?}`.
- `GET /report.xlsx?date` — Excel-сводка.
Право `dispatch` (`require_write`); ошибки 400/404/409; аудит; commit.

### `app/dispatch_reports.py` — Excel
Книга по дате: лист «Выпуск» (выходы: маршрут, водитель, автобус, план/факт,
отклонение, статус, причина) и лист «Регулярность» (рейсы: план/факт/отклонение/
вовремя) + строка сводки. Через существующие xlsx-хелперы.

### Фронтенд `static/dispatch.js` + `VIEWS.dispatch`
Вкладка «Диспетчер» в группе «Оперативная работа» (после «Наряд на день»).
Выбор даты; тумблер источника `Ручной | GPS`; подвкладки:
- **Выпуск** — таблица выходов; в ручном режиме кнопки статусов (Выпустить/На
  линии/Сошёл·причина/Срыв·причина/Замена), время редактируемо; в GPS-режиме
  кнопки скрыты, показывается «по GPS» и **кнопка-симулятор** «Смоделировать
  выпуск», отправляющая телеметрию.
- **Регулярность** — по выбранному выходу список рейсов с вводом факта и меткой
  «вовремя»; процент регулярности.
- Сводка КПД сверху. Кнопка «Отчёт Excel».
Право `dispatch` управляет доступностью действий. Версии ассетов подняты.

### Схема, права, демо
- 3 таблицы + индексы (`idx_dispatch_outputs_date`, UNIQUE order_line_id,
  `idx_dispatch_trip_facts_line`); настройка `dispatch_tolerance_min`.
- `WRITE_ACCESS`: `dispatch` для `диспетчер` и `эксплуатация` (админ — всё).
- Сид: для сегодняшнего наряда — часть выходов «выпущен»/«на линии», один
  «срыв», несколько фактов рейсов; режим дня `manual`.

## Обработка ошибок
- Нет наряда/утверждения на дату → пустое табло с флагом (не ошибка).
- Недопустимый переход статуса, отсутствие причины для сход/срыв/замена,
  некорректное время, неизвестный режим → 400.
- Несуществующий выход/строка/дата → 404.
- Телеметрия в ручном режиме или по неизвестному автобусу → 409/404.
- Нет права `dispatch` → 403. Доменные ошибки — подкласс `ValueError`.

- **Фронтенд**: вкладка/подвкладки/тумблер/кнопка-симулятор, версии ассетов;
  JS-тест расчёта отклонения и метки «вовремя».

## Границы (YAGNI)
Не включаем: реальную GPS-интеграцию и карту позиций в реальном времени (только
шов приёма телеметрии + симулятор), автоматическое перестроение наряда при срыве,
мобильное приложение водителя, пуш-уведомления вовне.
