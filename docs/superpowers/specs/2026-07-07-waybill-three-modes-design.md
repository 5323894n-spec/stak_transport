# Три режима оформления путевых листов

Дата: 2026-07-07

## Цель

Администратор должен управлять правилами оформления путевых листов из административной панели. Система должна поддерживать три режима контроля отметок медика и контрольного механика, а диспетчер должен иметь возможность массово оформлять и печатать путевые листы в наряде.

## Режимы

Настройка хранится в `settings` под ключом `waybill_issue_mode`.

Значения:

- `strict_med_tech` — нельзя оформить ПЛ без допуска медика и разрешения механика.
- `medical_only` — нельзя оформить ПЛ без допуска медика; отсутствие разрешения механика не блокирует оформление, но даёт предупреждение.
- `advisory` — ПЛ можно оформить и печатать без отметок медика и механика; все нарушения показываются как предупреждения.

Режим по умолчанию: `strict_med_tech`, чтобы сохранить текущую строгую логику.

## Правила блокировок и предупреждений

Общие блокировки во всех режимах:

- строка наряда не найдена;
- наряд не утверждён, не выдан и не скорректирован;
- не назначен водитель;
- не назначен автобус;
- в карточке водителя не заполнено водительское удостоверение;
- в карточке водителя не заполнен СНИЛС;
- истёк срок действия водительского удостоверения;
- у автобуса не заполнен госномер.

Режим `strict_med_tech`:

- нет предрейсового/предсменного медосмотра — блокировка;
- результат медосмотра не `допущен` — блокировка;
- нет предрейсового техконтроля — блокировка;
- результат техконтроля не `выпуск разрешен` — блокировка.

Режим `medical_only`:

- нет предрейсового/предсменного медосмотра — блокировка;
- результат медосмотра не `допущен` — блокировка;
- нет предрейсового техконтроля — предупреждение;
- результат техконтроля `выпуск запрещен` — блокировка, потому что это явный запрет выпуска;
- иной результат техконтроля, отличный от `выпуск разрешен`, — предупреждение.

Режим `advisory`:

- нет предрейсового/предсменного медосмотра — предупреждение;
- результат медосмотра не `допущен` — предупреждение;
- нет предрейсового техконтроля — предупреждение;
- результат техконтроля не `выпуск разрешен` — предупреждение.

## API и данные

Backend должен разделить проверку ПЛ на `problems` и `warnings`.

`GET /api/waybills/precheck/{line_id}` возвращает:

- `mode` — текущий режим;
- `problems` — блокирующие причины;
- `warnings` — предупреждения, которые не мешают оформлению.

`POST /api/waybills/from-line/{line_id}`:

- создаёт ПЛ, если нет блокирующих `problems`;
- в строгом режиме сохраняет ссылки на медосмотр и техконтроль;
- в режимах, где отметка не обязательна, допускает `NULL` в `medical_check_id` или `tech_check_id`;
- возвращает номер ПЛ и список предупреждений.

`POST /api/waybills/from-order/{date}`:

- оформляет все возможные ПЛ по наряду с учётом текущего режима;
- возвращает `created`, `blocked`, `warnings`;
- предупреждения не должны останавливать массовое оформление.

Новый endpoint для общей печати:

`GET /api/orders/waybills/print?date=YYYY-MM-DD`

Он печатает все неаннулированные ПЛ по наряду за выбранную дату, каждый ПЛ отдельным комплектом страниц.

Дополнительный endpoint для удобства:

`POST /api/waybills/from-order/{date}?print_all=1` не нужен. Формирование и печать лучше оставить двумя явными действиями на frontend: сначала массовое оформление, затем открытие общей печатной формы.

## Интерфейс

В `Настройки` для администратора добавляется блок `Правила оформления путевых листов` с выбором из трёх режимов:

1. `Медик и механик обязательны`
2. `Обязателен только медик`
3. `Свободное оформление с предупреждениями`

В модуле `Наряд` добавляются кнопки:

- `Оформить путевые листы` — массовое оформление по текущему режиму;
- `Печать всех ПЛ` — печать уже оформленных ПЛ наряда;
- `Сформировать и печатать все ПЛ` — сначала массово оформляет недостающие ПЛ, затем открывает общую печать.

При одиночном оформлении ПЛ:

- блокировки показываются как ошибка;
- предупреждения показываются пользователю, но ПЛ оформляется.

В модуле `Медосмотр / Техконтроль` информационная строка должна зависеть от режима, чтобы пользователи видели текущие правила оформления.

## Печатная форма

Если ПЛ создан без медосмотра или техконтроля:

- печатная форма открывается без ошибки;
- соответствующие поля отметок остаются пустыми;
- на самой форме не добавляется отдельный красный штамп, чтобы не портить официальный бланк.

## Проверки

Нужны тесты:

- режим `strict_med_tech` блокирует ПЛ без медика и механика;
- режим `medical_only` блокирует ПЛ без медика, но допускает отсутствие техконтроля с предупреждением;
- режим `medical_only` блокирует явный `выпуск запрещен`;
- режим `advisory` создаёт ПЛ без медика и механика с предупреждениями;
- массовое оформление учитывает режим и не останавливается на предупреждениях;
- общая печать наряда возвращает HTML со всеми оформленными ПЛ.

## Не входит в эту задачу

- изменение юридической формы бланка ПЛ;
- электронные подписи медика и механика;
- отдельная ролевая настройка доступа к каждому режиму;
- автоматическое создание отметок медика или механика.
