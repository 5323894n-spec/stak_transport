# Ручная корректировка линии трассы на карте

Дата: 2026-07-29  
Статус: согласованный дизайн

## Цель

На вкладке «Схема» карточки маршрута пользователь с правом изменения маршрутов должен иметь возможность вручную исправлять форму линии трассы на карте OpenStreetMap. Изменения сохраняются отдельно для прямого и обратного направлений, не перемещают остановки и не теряются при перезапуске программы.

## Границы задачи

В задачу входят:

- постоянное хранение геометрии прямого и обратного направлений;
- ручной режим редактирования контрольных точек в Leaflet;
- обязательная привязка линии ко всем остановкам направления;
- сохранение, отмена и сброс линии;
- безопасное взаимодействие с предпросмотром OSRM;
- аудит, контроль версий и серверная валидация;
- проверки API и поведения интерфейса.

В задачу не входят:

- свободное рисование трассы кистью;
- автоматическое притягивание ручной точки к ближайшей дороге;
- изменение координат остановки через редактор линии;
- одновременное отображение и редактирование двух направлений;
- история всех геометрий с возможностью восстановления произвольной версии.

## Модель данных

Добавляется таблица `route_geometries`:

- `id` — первичный ключ;
- `route_id` — маршрут с каскадным удалением;
- `direction` — только `forward` или `backward`;
- `geometry_json` — GeoJSON `LineString`;
- `source` — `manual` или `osrm`;
- `version` — положительное целое число для оптимистической блокировки;
- `updated_by` — имя пользователя;
- `created_at` и `updated_at` — служебные даты.

Пара `(route_id, direction)` уникальна. Миграция повторно безопасна и не изменяет существующие маршруты. Пока сохранённой геометрии нет, карта продолжает строить резервную линию по координатам остановок.

Полная геометрия хранится в формате GeoJSON:

```json
{
  "type": "LineString",
  "coordinates": [[35.9, 56.8], [35.91, 56.805]]
}
```

Порядок координат — долгота, затем широта. Контрольные точки не хранятся отдельно: ими являются редактируемые вершины сохранённой линии. В интерфейсе показывается разреженный набор обычных вершин и все обязательные вершины остановок, чтобы длинная трасса не перегружалась маркерами. При добавлении точки в линию создаётся новая вершина полной геометрии.

## Обязательная привязка к остановкам

Все остановки выбранного направления являются неподвижными обязательными вершинами линии. При подготовке черновика клиент сопоставляет остановку с вершиной геометрии по координатам с допустимым географическим отклонением не более `0.000001` градуса по каждой оси.

Сервер при сохранении повторяет эту проверку и отклоняет линию, если:

- у остановки отсутствуют координаты;
- координаты остановки не встречаются в линии в правильной последовательности;
- обязательная вершина была удалена или перемещена.

Остановки отображаются отдельными крупными пронумерованными маркерами. Перетаскивание этих маркеров в режиме редактирования геометрии запрещено. Координаты остановок по-прежнему меняются только существующим редактором остановки.

## API

### Чтение

`GET /api/routes/{route_id}/network` дополнительно возвращает:

```json
{
  "geometries": {
    "forward": {
      "geometry": {"type": "LineString", "coordinates": []},
      "source": "manual",
      "version": 3,
      "updated_by": "admin",
      "updated_at": "2026-07-29T12:00:00"
    },
    "backward": null
  }
}
```

Отсутствующее направление возвращается как `null`.

### Сохранение ручной линии

`PUT /api/routes/{route_id}/geometry/{direction}` принимает:

```json
{
  "geometry": {"type": "LineString", "coordinates": []},
  "expected_version": 3
}
```

Для первой записи `expected_version` равен `0`. Сервер атомарно валидирует и сохраняет линию с источником `manual`, увеличивает версию и возвращает актуальную запись.

Если версия не совпала, сервер возвращает `409` без записи данных. Если маршрут или остановка были изменены другим пользователем, интерфейс сохраняет локальный черновик и предлагает перезагрузить данные.

### Сброс

`DELETE /api/routes/{route_id}/geometry/{direction}` принимает `expected_version` в JSON-теле. После удаления карта использует резервную линию по остановкам. Удаление требует подтверждения пользователя и записывается в аудит.

### OSRM

Существующий `POST /api/routes/{route_id}/osrm/preview/{direction}` не изменяет сохранённую геометрию. Ответ содержит рассчитанный GeoJSON для предпросмотра.

`POST /api/routes/{route_id}/osrm/apply/{direction}` после проверки preview-токена атомарно:

1. применяет рассчитанные расстояния к перегонам;
2. сохраняет геометрию с источником `osrm`;
3. увеличивает версию геометрии;
4. записывает одно согласованное действие в аудит.

В запрос применения добавляется `expected_geometry_version`. Конфликт возвращает `409`, а текущая ручная линия остаётся без изменений.

## Серверная валидация

Сервер принимает только GeoJSON `LineString` и проверяет:

- не менее двух координат;
- не более 20 000 координат;
- каждая координата состоит ровно из двух конечных чисел;
- долгота находится в диапазоне от `-180` до `180`;
- широта находится в диапазоне от `-90` до `90`;
- соседние координаты не дублируются;
- все остановки направления присутствуют в правильной последовательности;
- JSON не превышает 2 МБ.

Ошибки контракта возвращают `400` с русским сообщением. Неизвестный маршрут возвращает `404`, недостаточные права — `403`, конфликт версии — `409`.

## Интерфейс карты

На вкладке «Схема» рядом с командами OSRM появляется кнопка «Корректировать линию». Она доступна только пользователю с правом изменения маршрутов и только при наличии координат у всех остановок направления.

После входа в режим:

- текущая линия копируется в локальный черновик;
- остановки становятся неподвижными обязательными маркерами;
- редактируемые вершины показываются небольшими маркерами;
- перемещение маркера сразу изменяет черновую линию на карте;
- щелчок по отрезку добавляет вершину в ближайшее место этого отрезка;
- щелчок по дополнительной вершине выделяет её;
- кнопка «Удалить точку» и клавиша `Delete` удаляют только выделенную необязательную вершину;
- кнопка «Отменить изменения» восстанавливает исходную линию без обращения к серверу;
- кнопка «Сохранить линию» вызывает API и закрывает режим только после успешного ответа;
- кнопка «Сбросить линию» удаляет сохранённую геометрию после подтверждения.

В режиме редактирования рядом с картой показывается краткая подсказка по действиям. Выбранная вершина имеет заметное состояние фокуса. Все команды доступны с клавиатуры, имеют русские `aria-label` и не зависят только от цвета.

При несохранённых изменениях смена направления, вкладки или закрытие карточки требует подтверждения. Если пользователь остаётся, черновик не меняется. Если подтверждает выход, черновик отбрасывается.

После сохранения карта показывает метку источника:

- «Ручная геометрия»;
- «Геометрия OSRM»;
- «Линия по остановкам» для резервного режима.

## Разрежение контрольных точек

Полная линия всегда отображается целиком. Чтобы не создавать тысячи маркеров, интерфейс показывает:

- все обязательные вершины остановок;
- первую и последнюю вершины;
- каждую N-ю дополнительную вершину, где N вычисляется так, чтобы одновременно было не более 120 редактируемых маркеров;
- вершины, добавленные пользователем в текущем черновике.

Непоказанную часть можно уточнить щелчком по линии: создаётся новая видимая вершина в выбранной позиции. Сохранение передаёт полную, а не разреженную геометрию.

## Взаимодействие с OSRM

Предпросмотр OSRM отображается поверх текущей линии контрастным пунктиром и не включает режим ручного редактирования. Одновременно может существовать только один из режимов: OSRM-предпросмотр или ручной черновик.

Если пользователь запускает OSRM при несохранённом ручном черновике, интерфейс просит подтвердить отказ от черновика. Применение OSRM заменяет сохранённую линию только после отдельного подтверждения. Отмена предпросмотра возвращает неизменённую текущую линию.

## Ошибки и конкурентное редактирование

Неудачный запрос сохранения:

- не закрывает режим редактирования;
- не удаляет локальный черновик;
- показывает сообщение сервера рядом с командами;
- позволяет повторить сохранение.

При `409` пользователь может скопировать или визуально сохранить свой черновик, затем перезагрузить актуальную трассу. Автоматического объединения двух геометрий нет.

Если картографическая подложка OpenStreetMap недоступна, ручной режим работает на существующей SVG/пустой подложке только для просмотра. Сохранение геометрии без Leaflet отключено, чтобы не создавать неточные координаты.

## Аудит

Сохранение, сброс и применение OSRM записывают:

- маршрут и направление;
- предыдущий и новый источник;
- предыдущую и новую версию;
- количество координат;
- пользователя и время.

Полная геометрия не дублируется в журнале аудита, чтобы не раздувать базу. Для диагностической связи достаточно версии и количества точек.

## Тестирование

### Схема и API

- повторно безопасная миграция и уникальность направления;
- каскадное удаление с маршрутом;
- чтение двух независимых направлений;
- создание, обновление и сброс геометрии;
- `403`, `404` и `409` без частичных изменений;
- аудит сохранения, сброса и OSRM-применения;
- отклонение неверного GeoJSON, диапазонов, бесконечных значений, лимитов и дубликатов;
- обязательные остановки и их порядок;
- атомарное применение расстояний и OSRM-геометрии.

### Интерфейс

- вход и выход из ручного режима;
- неподвижность остановок;
- перетаскивание, добавление, выделение и удаление вершины;
- невозможность удалить обязательную вершину;
- разрежение маркеров без изменения полной линии;
- сохранение и отмена;
- сохранение черновика после ошибки API;
- защита при смене вкладки и направления;
- конфликт версии;
- права только на чтение;
- взаимное исключение ручного режима и OSRM-предпросмотра;
- согласованные cache-key для изменённых ресурсов.

### Приёмочная проверка

1. Открыть прямое направление реального маршрута с геометрией OSRM.
2. Включить корректировку, добавить точку на ошибочном отрезке и перетащить её на нужную улицу.
3. Убедиться, что все остановки остались на линии и не переместились.
4. Сохранить, обновить страницу и проверить сохранённую форму и метку «Ручная геометрия».
5. Повторить для обратного направления и убедиться в независимости линий.
6. Запустить OSRM, отменить предпросмотр и убедиться, что ручная линия сохранилась.
7. Применить новый OSRM-предпросмотр и проверить замену линии только после подтверждения.

## Критерии готовности

Функция готова, когда пользователь с правом изменения маршрутов может вручную исправить отдельный участок трассы, сохранить его отдельно для каждого направления, увидеть тот же результат после перезагрузки, безопасно отменить изменения и использовать OSRM без молчаливой потери ручной линии. Все остановки остаются обязательными неподвижными вершинами, а ошибки и конфликты не уничтожают локальный черновик.
