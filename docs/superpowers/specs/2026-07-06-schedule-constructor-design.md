# Дизайн: модуль «Расписания» как операционный конструктор

Дата: 2026-07-06  
Проект: `ATP_servis_v2/atp-system`  
Решение: вариант A, операционный конструктор расписаний

## Цель

Доработать существующий модуль «Расписания маршрутов» до удобного рабочего экрана для специалиста эксплуатации и диспетчера. Первый релиз должен позволять быстро создать расписание автоматически, вручную поправить рейсы, увидеть выходы, проверить ошибки, оценить потребность в автобусах и водителях, посмотреть временную шкалу и выгрузить расписание в Excel.

Решение строится поверх текущей модели `route_trips`, `routes` и существующих API в `app/api_planning.py`. Полноценные версии расписаний, утверждение расписаний как отдельная бизнес-сущность и импорт Excel остаются будущими этапами, чтобы первый релиз не требовал глубокой перестройки базы.

## Пользователи и сценарии

Основные пользователи первого релиза:

- специалист отдела эксплуатации создает и корректирует расписания маршрутов;
- диспетчер просматривает готовое расписание и видит проблемы перед формированием графиков и нарядов;
- руководитель может быстро оценить рейсы, выходы, пробег и ошибки.

Ключевой сценарий:

1. Пользователь выбирает маршрут и тип дня.
2. Видит сводные показатели текущего расписания.
3. Запускает мастер генерации или добавляет рейсы вручную.
4. Проверяет ошибки и рекомендации.
5. Корректирует отдельные рейсы или выполняет массовые действия.
6. Смотрит временную шкалу по выходам.
7. Выгружает расписание в Excel.

## Подход

Выбран инкрементальный подход:

- сохранить простую архитектуру текущего прототипа: FastAPI, SQLite, SPA без сборки;
- улучшить существующий экран `VIEWS.schedule`;
- добавить небольшие backend-эндпоинты для сводки, массовых операций и экспорта;
- не вводить новую таблицу версий в первом релизе;
- не ломать данные, которые уже используются графиками, нарядами и путевыми листами.

## Функциональный объем первого релиза

### Экран расписаний

Верхняя панель:

- выбор маршрута;
- выбор типа дня: `будни`, `суббота`, `воскресенье`;
- поиск по рейсам, выходу, направлению и времени;
- быстрый индикатор состояния: корректно, предупреждения, ошибки, критично.

Сводные карточки:

- количество рейсов;
- количество выходов;
- расчетная потребность в автобусах;
- расчетная потребность в водителях;
- общий пробег;
- время первого и последнего рейса;
- количество ошибок и предупреждений.

Кнопки действий:

- `Сгенерировать расписание`;
- `+ рейс`;
- `Проверить ошибки`;
- `Сдвинуть время`;
- `Перенумеровать`;
- `Excel`.

Основные блоки экрана:

- `Рейсы`: большая таблица с фильтрами и подсветкой проблем;
- `Выходы и смены`: агрегированная таблица по выходам и сменам;
- `Временная шкала`: визуальная шкала по выходам, где каждый рейс показан блоком по времени;
- `Ошибки`: панель проверок с уровнем, местом, причиной и рекомендацией.

### Мастер генерации

Мастер остается модальным окном, но расширяется параметрами:

- количество выходов;
- первое отправление;
- последнее отправление;
- время прямого рейса;
- время обратного рейса;
- интервал;
- межрейсовый отстой;
- обед или пересменка;
- пробег прямого рейса;
- пробег обратного рейса;
- режим генерации: по интервалу или по количеству выходов.

В первом релизе backend сохраняет текущую модель генерации по интервалу и выходам. Режим «по количеству выходов» рассчитывает интервал из оборотного времени и количества выходов, если пользователь выбрал этот режим.

### Ручное редактирование

Сохраняется редактирование отдельного рейса через модальное окно.

Добавляются массовые действия:

- сдвиг всех рейсов выбранного типа дня на N минут;
- сдвиг рейсов конкретного выхода на N минут;
- автоматическая перенумерация рейсов внутри каждого выхода.

После каждого изменения пользователь остается на экране расписаний, а проверка пересчитывается при следующей загрузке.

### Проверки расписания

Текущие проверки расширяются:

- пересечение рейсов в одном выходе;
- слишком короткий отстой;
- отсутствие обеда или пересменки при длинном выходе;
- превышение длительности смены без деления;
- невозможное время прибытия;
- дублирование номера рейса внутри выхода;
- нарушение заданного интервала между отправлениями по маршруту;
- пустые обязательные поля рейса.

Каждая проблема возвращает:

- уровень: `предупреждение`, `ошибка`, `критично`;
- выход;
- рейс, если применимо;
- сообщение;
- рекомендацию.

### Экспорт

Добавляется Excel-экспорт расписания:

- маршрут;
- тип дня;
- выход;
- смена;
- номер рейса;
- направление;
- отправление;
- прибытие;
- длительность;
- пробег;
- отстой;
- тип перерыва.

Экспорт использует существующий helper `xlsx_response` из `app/xl.py`.

## UI-дизайн

Дизайн остается в стиле текущего приложения: светлая корпоративная тема, плотные таблицы, панели и бейджи. Новые элементы должны не выбиваться из текущих `panel`, `toolbar`, `grid`, `badge`, `card`.

Новые CSS-компоненты:

- `schedule-hero`: верхняя рабочая зона с маршрутом и статусом;
- `schedule-kpis`: компактные карточки показателей;
- `schedule-layout`: сетка для таблицы, шкалы и панели ошибок;
- `timeline`: горизонтальная шкала времени;
- `timeline-row`: строка одного выхода;
- `timeline-trip`: блок рейса;
- `trip-row-error`, `trip-row-warning`: подсветка строк таблицы.

Цветовая логика:

- зеленый: корректно;
- желтый: предупреждение;
- красный: ошибка или критично;
- синий: информационные элементы;
- серый: пустые или неактивные состояния.

## Backend-дизайн

Файл: `app/api_planning.py`.

Новые или расширенные функции:

- `schedule_summary(con, route_id, day_type)`: считает рейсы, выходы, потребность, пробег, время, проблемы;
- `route_check(...)`: возвращает более структурированные проблемы;
- `trips_generate(...)`: принимает расширенные параметры генерации;
- `POST /api/trips/bulk-shift`: массовый сдвиг времени;
- `POST /api/trips/renumber`: перенумерация рейсов;
- `GET /api/routes/{rid}/schedule-summary`: сводка для верхних карточек;
- `GET /api/routes/{rid}/schedule-export.xlsx`: Excel-экспорт расписания.

Существующие эндпоинты `/api/trips`, `/api/trips/generate`, `/api/routes/{rid}/check` сохраняются совместимыми с текущим frontend.

## Frontend-дизайн

Файл: `static/app.js`.

Изменяется `VIEWS.schedule`:

- загружает рейсы, проверку и сводку параллельно;
- хранит локальные фильтры в `window._sched`;
- рисует сводные карточки;
- рисует таблицу рейсов с подсветкой;
- рисует блок выходов;
- рисует временную шкалу;
- рисует панель ошибок.

Добавляются функции:

- `scheduleStatusBadge(summary)`;
- `scheduleCards(summary)`;
- `scheduleTimeline(trips, problems)`;
- `tripProblemMap(problems)`;
- `schedBulkShift()`;
- `schedRenumber()`;
- `schedExport()`.

Файл: `static/styles.css`.

Добавляются только стили для новых компонентов расписаний. Общую тему приложения не менять.

## Данные и совместимость

Новые таблицы в первом релизе не требуются.

Существующая таблица `route_trips` остается источником рейсов. Поля `break_after_min` и `break_type` используются для отстоя, обеда и пересменки. Данные из расписаний продолжают использоваться графиками, нарядами и путевыми листами через существующий `outputs_summary`.

## Обработка ошибок

Если расписание пустое, экран показывает понятное пустое состояние с кнопками генерации и добавления рейса.

Если массовое действие получает некорректный сдвиг, backend возвращает ошибку 400.

Если маршрут не найден, backend возвращает 404.

Если экспорт вызывается для пустого расписания, создается Excel с заголовками и пустым списком рейсов, чтобы пользователь получил предсказуемый результат.

## Тестирование

В проекте нет существующей тестовой директории. Для первого релиза добавить `pytest`-тесты в `tests/test_schedule_api.py`. Тесты используют FastAPI `TestClient` и временную SQLite-базу через переменную окружения `ATP_DB`, чтобы не менять рабочий файл `atp.db`.

- генерация расписания создает рейсы и выходы;
- проверка ловит пересечение рейсов;
- проверка ловит короткий отстой;
- массовый сдвиг меняет отправление и прибытие;
- перенумерация сортирует рейсы внутри выхода;
- сводка считает рейсы, выходы, пробег и потребность.

Если `pytest` отсутствует в окружении, добавить его в `requirements.txt` как тестовую зависимость проекта.

Дополнительно выполнить ручную проверку в браузере:

- открыть приложение;
- войти demo-пользователем;
- открыть «Расписания маршрутов»;
- сгенерировать расписание;
- добавить рейс вручную;
- выполнить массовый сдвиг;
- выполнить перенумерацию;
- скачать Excel.

## За рамками первого релиза

Не входят в первый релиз:

- отдельная таблица версий расписаний;
- статусы `черновик`, `на проверке`, `утверждено`, `архив`;
- сравнение версий;
- импорт расписаний из Excel;
- PDF, Word и остановочные печатные формы;
- drag-and-drop редактирование временной шкалы;
- автоматический подбор автобусов и водителей в самом модуле расписаний;
- интеграция с 1С из расписаний напрямую.

Эти функции можно добавить вторым этапом после стабилизации операционного конструктора.

## Критерии готовности

Первый релиз считается готовым, если:

- пользователь видит современный экран расписаний с карточками, таблицей, выходами, временной шкалой и ошибками;
- можно автоматически сгенерировать расписание;
- можно вручную добавить, изменить и удалить рейс;
- можно массово сдвинуть время рейсов;
- можно перенумеровать рейсы;
- проверки показывают понятные предупреждения и ошибки;
- сводка корректно считает рейсы, выходы, пробег, автобусы и водителей;
- Excel-экспорт скачивается;
- backend-тесты и ручная браузерная проверка проходят.
