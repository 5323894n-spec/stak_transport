# АТП-система: расписания, графики, наряды, путевые листы, табель, топливо, 1С

Запуск (из этой папки):

    pip install -r requirements.txt
    python run.py --demo

Затем откройте в браузере: **http://127.0.0.1:8000**

`--demo` при первом запуске наполняет базу демонстрационным АТП (30 водителей,
20 автобусов, 6 маршрутов, график на 2 месяца, наряды и путевые листы за вчера
и сегодня). Для чистой базы: `python run.py`. Другой порт: `python run.py --port 8080`.

Пользователи: **admin/admin** (администратор), а также dispatcher, ekspl, kadry,
buh, mech, med, fuel, dir — пароль **12345**. После внедрения смените пароли
(Настройки → Пользователи).

## Модули

Расписания маршрутов (рейсы, выходы, смены, проверка стыковок) · Графики
водителей (шаблоны 2/2, 5/2, 6/1 и др., отсутствия, резерв) · Проверка по
Приказу Минтранса № 424 (смена, время управления, перерывы, междусменный и
еженедельный отдых, переработки; критичные нарушения блокируют утверждение) ·
Наряды (автоформирование, замены с проверками, утверждение, печать) · Путевые
листы по форме № 6 (оформление только при утверждённом наряде, медосмотре и
техконтроле; сквозная нумерация, журнал, дубликат, аннулирование) · Медосмотры
и техконтроль · Табель (ночные, праздничные, сверхурочные к норме календаря) ·
Выгрузка в 1С (CSV/XML/JSON/Excel, коды времени, версии) · Топливо (нормы,
заправки, экономия/перерасход, аномалии) · Отчёты · Производственный календарь ·
Импорт/экспорт Excel · Аудит всех действий · Уведомления.

## Нормативы без правки кода

Раздел «Нормативы (Приказ 424)»: все параметры хранятся в базе версиями с
датами действия. При изменении законодательства администратор создаёт новую
версию — проверки автоматически применяют версию, действующую на дату.

> Перед промышленной эксплуатацией сверьте предустановленные значения
> с действующими редакциями Приказов Минтранса № 424 и № 390.

## Структура

    run.py              запуск (uvicorn)
    atp.db              база данных SQLite (создаётся автоматически)
    app/db.py           схема БД, нормативы по умолчанию, аудит
    app/auth.py         пользователи, сессии, роли
    app/norms.py        движок проверок № 424, расчёт часов
    app/api_refs.py     справочники, календарь, отсутствия, нормативы, импорт
    app/api_planning.py расписания, выходы, графики, наряды
    app/api_waybills.py медосмотры, техконтроль, путевые листы, печать
    app/api_time.py     табель, 1С, топливо, отчёты, главная панель
    app/seed.py         демо-данные
    static/             web-интерфейс (index.html + app.js + styles.css)

Резервная копия — файл `atp.db`. Это прототип на упрощённом стеке (SQLite,
один процесс); перевод на PostgreSQL — замена слоя `app/db.py`.
## Ремонт и ТО

Раздел «Ремонт и ТО» поддерживает полный цикл: заявка, заказ-наряд, исполнители,
операции, складские запчасти, контрольный осмотр, закрытие, история автобуса,
плановое ТО, календарь, уведомления, Excel-отчёт и печатная форма. Автобус с
активным ремонтом нельзя назначить в наряд, допустить техническим контролем или
оформить в путевой лист.

Роли модуля: `мастер ремонта` создаёт и ведёт заказ-наряды; `слесарь` выполняет
работы; `механик контроля` проводит контрольный осмотр; `склад` выдаёт и
возвращает детали; `руководитель` читает отчёты; `админ` имеет полный доступ.
Администратор настраивает период повторной неисправности в «Настройки →
Настройки ремонта и ТО».

Вложения хранятся в каталоге из переменной `ATP_REPAIR_UPLOADS`; без неё
используется каталог приложения. Допустимы PDF, JPG/PNG, DOCX и XLSX размером до
10 МБ. Скачивание выполняется только через авторизованный API.

Перед обновлением остановите приложение и скопируйте `atp.db` в безопасное
место. Миграции выполняются автоматически и повторный запуск безопасен. Для
отката остановите приложение и восстановите сохранённую копию базы. Проверка:

    python -m pytest -q

Excel-отчёт доступен кнопкой «Отчёт ремонта Excel», печатная форма — кнопкой
«Печать» в строке заказ-наряда. Подробный порядок работы описан в
`docs/Ремонт_и_ТО_инструкция.md`.
